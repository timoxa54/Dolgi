# 🎓 Dolgi — планировщик закрытия долгов

**Dolgi** — десктопное Python-приложение (CustomTkinter) для планирования закрытия академических задолженностей в БГПУ.

Приложение авторизуется в личном кабинете БГПУ, берёт долги из зачётной книжки, собирает расписания преподавателей и своей группы, сопоставляет их и строит оптимальный план посещений.

> ⚠️ Проект для личного использования. Авторизация — под учётной записью самого пользователя. Логин и пароль хранятся локально в `.env` и не попадают в Git.

---

## 📌 Что умеет

```text
Вход в личный кабинет БГПУ (логин/пароль из .env)
        ↓
[Загрузить долги]      — зачётная книжка → карточки долгов
        ↓
Карточки долгов        — правка предмета, преподавателя, оценки,
                         удаление из учёта, переключатель «учитывать»
        ↓
[Загрузить расписания] — расписания преподавателей долгов + своей группы
        ↓
[Построить план]       — сопоставление предметов и оптимизация:
                         максимум долгов → минимум дней →
                         минимум переходов между корпусами → комфортность
        ↓
Готовый план по дням   — время, предмет, преподаватель, корпус/аудитория
```

Все данные хранятся локально в папке `data/` (`debts.json`, `schedule.json`, `settings.json`), поэтому правки карточек сохраняются между запусками.

**Особенности:**

* долги с пустой оценкой долгом не считаются (как на сайте);
* удалённый из учёта долг не возвращается при повторном парсинге;
* отредактированные карточки не теряются при повторной загрузке долгов;
* группа из зачётки — код индивидуальной группы; если у неё нет расписания, впиши в поле «Твоя группа» свою учебную группу (например, `ПИНФ_ПИЦЭ-31-24`).

# 🚀 Быстрый запуск

## 1. Требования

* Windows 10/11;
* Python 3.12+;
* аккаунт студента БГПУ;
* браузер Chromium для Playwright.

## 2. Установка

```powershell
git clone https://github.com/timoxa54/Dolgi.git
cd Dolgi
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
playwright install chromium
```

Если PowerShell блокирует запуск: `Set-ExecutionPolicy -Scope Process Bypass`.

## 3. Настройка `.env`

```env
BSPU_LOGIN=твой_логин
BSPU_PASSWORD=твой_пароль
TELEGRAM_BOT_TOKEN=...   # зарезервировано на будущее, пока не используется
TELEGRAM_ADMIN_ID=...    # зарезервировано на будущее, пока не используется
```

Файл `.env` добавлен в `.gitignore` и не попадает в репозиторий.

## 4. Запуск

```powershell
python main.py
```

## Собранный exe

Готовый `Dolgi.exe` собирается командой:

```powershell
pyinstaller --noconsole --onefile --name Dolgi --collect-all customtkinter --collect-all playwright main.py
```

Результат — `dist\Dolgi.exe`. Рядом с ним должны лежать:

* `.env` — скопируйте его в папку `dist\`;
* браузеры Playwright в `%LOCALAPPDATA%\ms-playwright` — ставятся один раз командой `pip install playwright && playwright install chromium` (используются и exe, и исходной версией).

---

1. Проверь логин/пароль (сохраняются в `.env` по кнопке).
2. **Загрузить долги** — войти на сайт, забрать зачётку, показать карточки.
3. **Загрузить расписания** — собрать расписания преподавателей из долгов и своей группы.
4. **Построить план** — показать оптимальный план на вкладке «План».

Ход операций виден на вкладке «Журнал», прогресс — в полосе прогресса.

```text
├── main.py              # точка входа (запуск GUI)
├── dolgi/
│   ├── config.py        # пути, адреса сайта БГПУ, работа с .env

│   ├── parsing/         # разбор HTML зачётки и расписаний
│   └── ui/              # окно приложения (CustomTkinter)
├── data/                # локальные данные (git-ignored)
├── legacy/              # старая консольная версия (git-ignored)
├── tests/               # проверки парсинга на сохранённых страницах
├── requirements.txt
└── .env                 # локальные данные авторизации (git-ignored)
```

# 🧠 Как работает оптимизация

1. Каждое занятие расписания, совпавшее с долгом по предмету (`exact` / `normalized` / `partial`), — кандидат.
2. Для каждого дня динамическим программированием строятся непересекающиеся наборы занятий (по маске долгов).
3. Глобальный перебор дней выбирает план: **максимум долгов → минимум дней → минимум переходов между корпусами → комфортность → минимум занятий**.

Комфортность дня учитывает переходы между корпусами, ожидание, длинные перерывы и общую продолжительность дня.
